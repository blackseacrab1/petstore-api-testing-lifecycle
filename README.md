Full-stack QA automation framework with API &amp; UI tests. Includes manual test reports via GitHub Pages.

# Внедрение автоматизации тестирования с нуля (PetStore API & UI)

Этот проект демонстрирует полный цикл построения процесса тестирования: от анализа требований и ручного исследования до создания гибридного фреймворка (API + UI) и настройки CI/CD пайплайнов. Проект разделен на два независимых этапа, каждый из которых имеет свою артефактную базу и конфигурацию сборки.

## Этап 1: Анализ, ручное тестирование и автоматизация API
Фокус на бэкенд-логике, контрактах и надежности данных. Используется Swagger PetStore как целевая система.

### 1. Анализ и работа с требованиями
*   Изучение Swagger/OpenAPI спецификации (`swagger.json`).
*   Выявление обязательных параметров, типов данных и ограничений.
*   Определение ключевых бизнес-правил и валидаций.

### 2. Исследовательское тестирование (Exploratory Testing)
*   Ручное изучение поведения API через Postman/Swagger UI.
*   Проверка граничных значений, негативных сценариев и безопасности.
*   Выявление скрытых зависимостей между ресурсами.

### 3. Ручное тестирование CRUD операций
*   Верификация базовых методов: Create, Read, Update, Delete.
*   Проверка целостности данных при переходе между операциями.
*   Валидация кодов ответов и структуры JSON.

### 4. Отчет о ручном тестировании API
*   Документирование результатов исследования.
*   Фиксация найденных особенностей и потенциальных багов.
*   [Ссылка на отчет об API тестировании](docs/api-test-report.md) *(GitHub Pages)*

### 5. Разработка фреймворка API автоматизации
*   Стек: Python + Pytest + Requests.
*   Реализация паттерна API Object для переиспользования запросов.
*   Параметризация тестов и управление тестовыми данными.
*   Настройка фикстур для подготовки и очистки окружения.

### 6. Интеграция CI/CD для API
*   Настройка GitHub Actions для автоматического запуска API-тестов при пуше.
*   Генерация Allure Report в пайплайне.
*   [Пример отчета Allure API](https://ivan.github.io/repo/allure-api/)

---

## Этап 2: Ручное UI-тестирование и последующая автоматизация E2E
Переход к пользовательскому интерфейсу после стабилизации API. Фокус на бизнес-сценариях, визуальной части и постепенном внедрении автотестов. Реализуется в отдельном репозитории.

### 1. Создание чек-листов и декомпозиция функционала
*   Разбивка приложения на модули (Авторизация, Каталог, Корзина).
*   Приоритезация критических путей пользователя (Critical User Journeys).
*   Составление чек-листов для регрессионного тестирования.

### 2. Ручное UI-тестирование (Research & Validation)
*   Прокликивание основных сценариев по чек-листам.
*   Кроссбраузерная проверка (Chrome/Firefox).
*   Валидация UX, доступности элементов и стабильности верстки.
*   Фиксация «хрупких» мест интерфейса перед автоматизацией.

### 3. Отчет о ручном UI-тестировании
*   Документирование результатов прокликивания сценариев.
*   Список нестабильных элементов и рекомендаций для автотестов.
*   [Ссылка на отчет о ручном UI-тестировании](docs/ui-manual-report.md) *(GitHub Pages)*

### 4. Разработка UI-фреймворка
*   Стек: Python + Playwright + Selenium + Pytest.
*   Реализация устойчивых локаторов и ожиданий.
*   Интеграция с API-частью для создания тестовых данных перед UI-проверкой.
*   [Ссылка на репозиторий UI автоматизации](https://github.com/ivan/ui-automation-repo)

### 5. Отчет об автоматизации UI
*   Статистика прохождения E2E сценариев.
*   Скриншоты падений и видео запусков.
*   [Ссылка на отчет об автоматизации UI](https://ivan.github.io/repo/ui-auto-report/)

### 6. CI/CD для UI автоматизации
*   Настройка отдельного GitHub Actions workflow для UI-репозитория.
*   Запуск тестов в headless-режиме и сохранение артефактов (видео/скриншоты).
*   Уведомления о результатах сборки.
*   [Конфигурация GitHub Actions UI](https://github.com/ivan/ui-automation-repo/blob/main/.github/workflows/ci.yml)
