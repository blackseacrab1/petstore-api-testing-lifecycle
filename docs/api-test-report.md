## 2. Детализация ключевых артефактов

### 🔍 GET /pet/findByStatus?status=available
-   **Request:** `GET https://petstore.swagger.io/v2/pet/findByStatus?status=available`
-   **Response Code:** `200 OK`
-   **Response Body:** `[]` (пустой массив)
-   **Комментарий:** Сервер вернул успешный статус, но данных нет. Возможно, все питомцы имеют статус `sold` или база была очищена. Для автотеста необходимо сначала создавать testData через POST.

### 🔄 PUT /pet (Полное обновление)
-   **Request Body:**
    ```json
    {
      "id": 1000,
      "name": "new_el_barto",
      "status": "sold",
      "photoUrls": [],
      "tags": []
    }
    ```
-   **Response Code:** `200 OK`
-   **Ключевой вывод:** PUT выполняет **полную замену** ресурса. Поля `photoUrls` и `tags`, переданные как пустые массивы, полностью удалили предыдущие значения. В автотестах для обновления одного поля необходимо сначала делать GET, получать текущие данные, модифицировать нужное поле и отправлять полный объект обратно.

---

## 3. Выводы для автоматизации

1.  **Нестабильность демо-данных:** Нельзя полагаться на предустановленных питомцев. Каждый автотест должен самостоятельно создавать свои testData через POST и удалять их после проверки.
2.  **Специфика PUT:** Требуется реализовать вспомогательную функцию `get_full_pet_object(id)` для безопасного обновления без потери данных.
3.  **Пустой список ≠ ошибка:** Автотесты на поиск должны проверять не только статус-код 200, но и наличие элементов в массиве, либо явно создавать данные перед поиском.
4.  **ID для тестов:** Использовать простые числа (777, 1000, 9999). Избегать значений > 2^53 из-за ограничений точности JSON в некоторых библиотеках.
